### 1.2 推測（待 ② 驗證）
- P1 RenderBox 貼圖用雙線性、無 mipmap：放大 → 邊緣變軟（最大差隨 r 上升）；縮小 → 走樣。推理鏈：F4 的差異隨 |r−1| 單調上升、r＝1 且 rot 0 幾乎沒差。
- P2 次像素相位：r＝1 也會因 origin 落在非整數裝置像素而被重取樣（等於 0.5 px 的模糊）。這可能是「照實際字級建」反而更差的原因（建在 r＝1 但相位全錯；或 box 取整的座標系不對）。
- P3 旋轉：任何旋轉都會重取樣（F4 rot 0.05 在 100 pt 也有 13,020），這部分**任何尺寸策略都無法消除**，只能靠插值品質或改走向量。

### 3.2 ② 根因機制（spike，不進 main）
在 scratchpad 開 detached worktree（deddbde）。**測試台＝正式路徑**：同一個字（Anton「W」與 Rock Salt「g」各一）、同一張 alpha-only 遮罩、同一個 Canvas＋`resolve`＋template shading＋`ImageRenderer` 2×，黑底白字不透明；比對對象是同一 transform 下的向量填色（R1 #3）。
- 「相位」定義（R1 #4）：最終「點陣像素 → 裝置像素」仿射矩陣的平移分量對 1 px 取餘，不是 `origin`。每格實驗輸出：完整矩陣、裝置空間 box、來源像素尺寸、插值設定、seed。
- 先做 M0 確定性：每格同畫法畫兩次，差須為 0。
- M1a 插值（固定 r＝1.25、rot 0、相位 0）：`Image.interpolation(.none/.low/.medium/.high)`、`antialiased(true/false)`，確認在 `single.draw(image, in:)` 這條路徑**是否生效**（輸出像素是否改變）。
- M1b 縮放（固定 M1a 選出的插值）：r ∈ {0.5, 0.67, 0.8, 1, 1.13, 1.25, 1.42, 2}，相位 0、rot 0。mipmap 在 Canvas 路徑不可控 → 列為不可操控因子，只從 r<1 的曲線形狀推論。
- M1c 來源解析度掃描（R1 #5、R2 R1-3）：**最終裝置空間的字形矩陣、相位、bounds 每格相同**（字級 113／142 pt、rot 0、相位 0），只改來源點陣的解析度 ∈ {0.5×, 0.75×, 1×, 1.5×, 2×, 3×} 目標像素（貼圖矩陣隨之反算）——直接驗證 F6「高解析縮小也更差」。
- M2 相位：r＝1、rot 0、scaleX/Y＝1、zoom＝1、無 shake，相位 ∈ {0, .25, .5, .75}（x、y 各掃）。
- M3 旋轉：r＝1、相位 0，rot ∈ {0, .01, .05, .1}。
- M4 重現「照實際字級建」：r＝1 時（a）相位錯（b）相位對，另檢查 box 取整的座標系。目的：解釋 293 紅是策略錯還是實作錯。
- M6 群組透明（R2 R1-3）：兩個重疊字、半透明 0.5，`.rasterGrouped` vs 合併外框，r＝1、相位 0 與 r＝1.25 各一格——量群組合成本身的差，與單字因素分開歸因。
- M5 比較基準（不是下限，R1 #3）：（a）逐字向量填 vs 合併外框（分離合併抗鋸齒）；（b）CG 在目標像素直接光柵化 vs RenderBox 向量填（兩條管線的差）。
- 產出：因素 × 貢獻表；根因寫成已核事實（附數據），解釋不了的寫 TBD。**熔斷**：M0–M6 做完仍解釋不了 F4 的主要差異，就停手回報，不另開新方向。

### 3.3 ③ 尺寸策略候選
- **候選的資格**：② 單字實驗顯示有機會讓該情境達標的策略才算候選；被 ② 否定的寫理由、不算候選（使用者要求「每個候選都量五項」，這裡不預篩候選內的量測）。
- **硬條件（R1 #1）**：一般字與 Anton 在所有 V3／V1 案例中**點陣覆蓋率 100%**（描邊例外，同現狀）。改走向量的做法不是候選。
- 暫定（② 後定案）：
  - C0 現狀（對照列）。
  - C1 較高插值品質：只在 M1a 證實該設定在 `single.draw` 路徑生效且改善時成立；記作用點與副作用。
  - C2 依有效裝置像素建點陣＋相位分格（R1 #2；**只解零旋轉子集**，R2 N3）。座標契約（R2 R1-2、N1）：
    - 三個空間：路徑空間 P（`GlyphPathCache.Entry` 座標，y 向下）；裝置空間 D（像素）；點陣像素空間 R。
    - 向量畫法的 P→D：`M = transform(for:) · 外層 CTM（shake、zoom、displayScale）`，寫成 `D = A·P + t`。C2 只在 A 為正對角 `diag(ax, ay)`（無旋轉、無斜切；x、y 可不等）時適用；其餘字走 C0 點陣（保 100% 覆蓋）。
    - 建點陣：`qx = round(ax / step)·step`、`qy` 同（量化步距 step 由 M1b 定），相位 `φ = frac(t)` 量化到 1/N 像素（N 由 M2 定）。光柵化矩陣 `R = diag(qx, qy)·P + φq − (bx, by)`，其中 `(bx, by)` 是 `diag(qx,qy)·bbox(P) + φq` 外擴 1 px 後取 floor 的整數像素原點。鍵 `(text, face, entry.size, qx, qy, φq)`。
    - 貼圖（R3 修正）：由 `R = Q·P + φq − b`（`Q = diag(qx, qy)`、`b = (bx, by)`）得 `P = Q⁻¹·(R − φq + b)`，代入 `D = A·P + t`：**`D = S·R + (t − S·(φq − b))`，`S = A·Q⁻¹ = diag(ax/qx, ay/qy)`**。落格（S＝I）時平移＝`floor(t) + b + (φ − φq)`，即整數像素平移加殘差相位 ≤ 1/(2N) px；不落格時另有殘差縮放 |S−I| ≤ step／(2q)——照實寫成近似，不宣稱零重取樣。
    - 實作：每字算出完整 R→D 仿射（上式），換成 Canvas 的點座標再設給 `GraphicsContext`（不沿用 `transform(for:)`）。「點座標 ↔ 裝置像素」的換算（`GraphicsContext.transform` 與 `displayScale` 的關係、外層 shake／zoom 是否都已在 `transform` 內）**先在 spike 以實測驗證**：畫 1 px 標記、讀回像素位置，與算出的矩陣比；不符就不做 C2、記理由。
    - 驗收測試：`scaleX ≠ scaleY` 的字，點陣在裝置空間的錨點／基線／bbox 與向量畫法的偏差 ≤ 殘差界限；落格的字偏差＝0。
    - 候選表的 V3 分列「C2 命中的字」與「落回 C0 的字」各自的指標與命中率，不以平均遮蔽落回的失敗。
  - C4 提高來源解析度：只在 M1c 顯示「高解析縮小」優於現狀、且以實際 `FramePlan` 枚舉出全測試域的最大有效縮放比後才成立。
- **每個候選都量五項**：
  - V3：900×560（2×、1× 判定）＋1728×945（2× 判定、1× 記錄），§3.1 矩陣。
  - V1 每幀：既有 7 份＋Anton 三份（含 neonstroke），Anton **強制走候選的點陣路徑**（spike 以 `AZW_SPIKE` 讓 Anton `rasterizes = true`；neonstroke 仍描邊走向量），量測摘要加逐字「點陣／向量」計數以證明覆蓋率（R2 N2）；**全螢幕**視窗（spike 加 DEBUG 旗標讓預覽全螢幕；正式實作時只在 `#if DEBUG`）；每份 6 窗丟第 1 窗，每窗 p50 ≤ 2 ms 且 p95 ≤ 3 ms；`front=NO` 重跑。
  - V2 主執行緒總量：Rock Salt、Catacombs、Anton LP；**基線＝同一個候選二進位、只把畫法切成 `.vectorReference`**（R1 #9）；3 輪以 ABBA、BAAB、ABBA 平衡起始臂；每臂前同一預熱流程（啟動後等 8 s 再錄，快取從空開始）；沿用 I-46 的前景每 0.25 秒取樣（任一次不是該 PID 作廢該輪）；trace 原檔與每輪數字保存。判定：3 輪平均 ≤ 向量基線 × 0.85。
